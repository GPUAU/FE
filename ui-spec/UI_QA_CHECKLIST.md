# UI QA 검증 기록

## 이전에 확인된 범위

- 브라우저: 대시보드 시장 전환, B200 선택, 가격 근거 열기·닫기, 환율 적용·초기화·금리 보기, 목록 검색, 이력 페이지 이동과 검색 없음.
- 이전 반응형 점검: 390px 비교·약정·대시보드·상품 목록, 원가 768·1024·1440px의 문서 폭과 일부 표 스크롤. 전체 페이지의 시각 점검은 아님.
- 테스트: 가격 이력 검색·정렬·페이지 경계·검색 없음 Node 테스트 4건.

## 이번 작업의 검증

아래는 실행 결과를 보고 추가한다. 전 페이지·모든 API·실패 주입·실제 화면 리더·WCAG 자동/수동 전체 검사·전체 브라우저는 아직 확인하지 않았다.

- 2026-11-18 실행 브라우저: 대시보드에서 1440/1024/768/390px viewport의 document scrollWidth 각각 1425/1009/753/375px. 문서 가로 넘침 없음. 390px 메뉴 열림·메뉴 링크 표시 확인. 이 수치는 대시보드 상단 영역의 검사이며 모든 요소가 네 폭에서 완벽하다는 의미는 아니다.
- B200 AWS 가격 근거 dialog 열기, Escape 닫기, 호출한 버튼으로 포커스 복귀 확인.
- 이력 검색 결과 없음, 검색 초기화 후 2/2 페이지 이동, 조건 비교 표본 없음, Agent 질문 버튼 비활성 확인.
- 대시보드 헤더 실측 64px(테두리 포함)로 LAYOUT_SPEC 목표 60px과 차이. 헤더 수정 시 메뉴의 sticky 기준과 함께 조정 필요.
- 토큰 색 대비 계산: #20242a/흰색 15.59:1, #596574/흰색 5.93:1, #596574/#f5f6f8 5.49:1, #d92335/흰색 4.95:1, #275da8/흰색 6.53:1. 실제 모든 컴포넌트의 조합을 검사한 것은 아니다.
- JavaScript 구문 검사 통과, 이력 로직 테스트 4건 통과.

## 미검증·후속 구현

- 전체 10개 이상 화면의 네 폭 스크린샷, 서버 중단·타임아웃·권한 오류 강제 검증, 모든 버튼·정렬·필터·pagination 회귀 테스트.
- 화면 리더, 접근성 자동 도구, 모든 색 대비·터치 크기, 모든 모달의 포커스 순회.
- 공통 component props/events의 실제 재사용 컴포넌트 구현, 기존 중첩 CSS 통합, 모든 화면의 로딩·오류·부분 데이터.
- 목표 레이아웃 수치와 현재 구현의 불일치 전수 측정 및 수정. 설정만으로 WCAG AA 준수를 주장할 수 없음.

## 추가 적용 및 검증

- 원가·사업성·할인·조건 비교·이력·품질의 폼·결과·표 스크롤에 공통 간격·색상·크기를 보완했다.
- 조건 비교에서 버튼/필터가 재생성돼 포커스가 본문으로 사라지던 문제를 수정했다. 브라우저에서 참고 비교 선택 후 포커스가 해당 버튼에 유지되고 10개 결과가 표시되는 것을 확인했다.
- 가격 이력은 기본 데이터 조회가 실패하는 경우도 기존 오류 안내와 재시도 경로로 전달하도록 범위를 확장했다. 서버 장애를 실제 주입해 검증하지는 않았다.
- 표 스크롤 컨테이너에 키보드 포커스와 레이블을 부여했다. 390px 원가 표에서 오른쪽 화살표로 스크롤 위치가 0→40px로 이동하는 것을 확인했다.
- 원가 계산: GPU 8개·가동률 80%·3년·서버 350,000 USD·목표 마진 30%의 예시에서 기준일 누락 안내 후 날짜 입력 시 조건부 결과가 표시됨을 확인했다. 연결된 사업성 화면에 원가 가정이 전달되었고 잔존가치 0·목표 IRR 10% 입력 시 조건부 결과를 확인했다.
- 390px에서 약정·품질·원가·사업성 페이지의 문서 가로 넘침이 없고 표가 내부 스크롤됨을 확인했다. 원가 화면은 768/1024/1440px에서도 document scrollWidth 753/1009/1425px로 각각 확인했다. 전체 페이지·전체 폭 조합의 시각 검증은 미실시.
- 여전히 전체 기능 회귀, 서버 실패·타임아웃 주입, 스크린리더와 색상 대비 전수 검사, 접근성 AA 인증은 미완료다.
