# 프론트 가격 검토 흐름 — 2026-11-19

진입: `http://127.0.0.1:18091/#decision` 또는 상단 가격 검토 메뉴.

## 구현한 네 가지

1. 원가 결과 또는 IRR 입력을 가격 검토로 가져온다. 가동률·목표 IRR 등을 확인해 계산하고 동일 입력을 IRR 상세 및 PM 시뮬레이션으로 전달한다. 원가·IRR·검토 입력 변경 시 관련 결과를 무효화하고 이전 요청의 늦은 응답도 연결하지 않는다.
2. 온디맨드·스팟·1년/3년 약정 상품을 GPU 모델, 과금 방식, 리전으로 선택한다. 후보가격과 저장 경쟁 단가의 차액/차이율, 선납 조건, 단가 기준, 수집 시각, 출처를 표시한다. 동일 조건 미판정을 참고 비교로 표시한다. 조회 일부 실패도 명시한다.
3. 사용자 입력 보수·기준·낙관 가동률에서 연 매출, 연 운영 현금흐름, IRR, 목표 IRR 필요가를 비교한다. 선택 시나리오를 현재 입력에 적용할 수 있다. 수요 예측값이나 확률분포로 표현하지 않는다.
4. 원가 하한과 목표 IRR 필요가 중 큰 값을 필요 하한으로 표시한다. 사용자 상한이 있으면 검토 구간을 표시하고, 상한 미입력/하한 초과/원가 불완전/후보가격 미충족을 구분한다. 최종 추천가격이나 검증된 시장 상한으로 표시하지 않는다.

## 계산 기준

- 경쟁 단가 차이 = 후보 − 경쟁 단가. 차이율 = 차이 ÷ 경쟁 단가 × 100. 유효한 양의 경쟁 단가가 없으면 계산하지 않는다.
- 가동률 비교는 기존 `GpuV02.investment`의 연간 현금흐름을 사용한다. 연 8,760시간, 현금 운영비 고정, 세전·무차입, 마지막 해 잔존가치 1회 반영.
- 원가 화면의 선택 월 결과는 연간 원가로 환산해 전달한다. 월 전기료를 단순히 12배 하지 않고 연 8,760시간의 전기료를 사용한다.
- 원가 입력을 직접 가져오지 않았거나 투자·운영비를 따로 수정하면 원가 완전성을 확인되지 않은 상태로 처리한다. 상위 입력 변경 후 남은 값은 이전 복사본이며 새 원가로 간주하지 않는다.

## PM 입력 변환

| 가격 검토 | PM 시뮬레이션 |
|---|---|
| 총 초기 투자금 / GPU 수 | GPU당 투자비 |
| 연간 현금 운영비 / GPU 수 / 12 | GPU당 월 운영비 |
| 분석 연수 × 12 | 투자 개월 |
| 잔존가치 / 총 초기 투자금 | 잔존가치 비율 |
| 현재 가동률 | 최소/최빈/최대 동일 값 |
| 후보가격, 목표 연 IRR | 후보가격 배열, 목표 IRR |

첫 연결은 고정 판매가, 가동 지연 0개월, 투자비 초과율/운영비 상승률 0으로 고정한다. 이때 불확실 변수가 고정되어 달성 확률이 0% 또는 100%로 나타날 수 있다. 사용자가 시뮬레이션 입력을 편집하면 공통 검토 결과와의 연결을 해제한다. 시장가 시나리오/추세 선택만 바꾸는 경우 동일 투자 입력 연결을 유지한다.

PM 월별 현금흐름과 IRR 화면의 연말 현금흐름은 수취 시점이 달라 같은 연 입력에서도 결과가 다를 수 있다. PM의 가상 B300 가격 18개월은 그대로 유지하며 다른 GPU 모델 예측으로 연결하지 않는다. PM 지원 범위는 12~60개월이다.

- 약정 상품 조회 및 선납 옵션 표시 확인. JSON 다운로드 후 입력/가동률 3개/경쟁 근거 확인.
- 모바일 및 데스크톱에서 페이지 전체 가로 넘침 없음 확인.
- PM 고정 입력을 기존 로컬 계산 API에 전달하여 수용 및 결과 확인. PM 엔진과 Spring 소스 변경 없음.

## 후속 연결 범위

실제 가격 이력 기반 예측, 서버의 동일 조건 판정·시장 상한·최종 추천, 백테스트 정확도, Agent는 이번 프론트 작업에서 구현하지 않았다. 저장/인증/결정 이력 API도 없다. 입력과 결과는 현재 탭 메모리에 있고 JSON 저장만 사용자가 선택해 내려받는다. PM 입력은 기존 로컬 계산 서버로 전달된다.
