# 1GW 데이터센터 운영 원가·판매가격 모형

사용자 결정: 2026-11-24, 직접 운영하는 데이터센터의 GPU 시간당 원가, 목표 마진 판매가격, 경쟁사 공개 가격을 검토하는 목적으로 제공 PDF의 1GW 모형을 적용한다. 기존 개별 원가 계산기는 출처/기준 섹션의 버튼으로 유지한다.

## 출처와 숫자

한종목, 미래에셋증권 리서치센터, 「AI Factory의 경제학」(2026-05-19), 사용자 제공 `20260519_AI Bottleneck Issue-8.pdf`, 14~16쪽 표 3~5. PDF 원문은 저장소에 재배포하지 않는다. 실측·실제 견적·최신 시장가격으로 표현하지 않는다.

## 원가 모형

- REPORT_FACTORS: 보고서의 각 연간 자본회수비용 / 각 취득비를 연간화 계수로 사용한다. 서버 약24%, 네트워크24%, 시설 약11.51%. 단일 공통 WACC로 역산하지 않는다. 기본값에서 보고서 총액과 일치한다. 사용자가 취득비를 바꾸면 동일 계수로 연간화한다. 보고서 모드에서는 IT 5년, 시설14년, 잔존가치0을 명시적으로 적용하고 다른 값을 API로 제출하면 거절한다.
- DISCOUNT_RATE: 기존 CRF 방식으로 자산별 내용연수·잔존가치를 사용한다. 연간 정액 감가상각은 별도 참고값이며 연 TCO에 자본회수비용과 중복 가산하지 않는다.
- 기타 운영비는 보고서의 총900M에서 표4의 전기료를 뺀 잔액이다. 인건비·보안·유지보수 등의 개별 견적을 임의로 만들지 않는다. 보고서 본문의 전기료 약590M과 표4의624.64932M이 달라 표4 기준을 명시한다.
- 전력은 설계 부하 × PUE × 평균 전력 부하율 ×8760×전력단가. 보고서 재현용 초기 모드는 전력 부하율과 유료 가동률을 같게 둔다. 실제 유휴전력을 고려할 수 있도록 별도 부하율 모드도 제공한다. API에서는 두 비율을 독립적으로 받는다.
- 랙 수는 연속형 등가 랙 수다. 설치 가능한 정수 랙 수도 올림하여 별도로 표시한다. 600,000/72=8,333.33 등가 랙이며 정수 설치는 최소8,334랙이다. 부하 계산은 보고서 재현을 위해 등가 랙을 사용한다. 부지면적/실제 설비용량의 확정 설계는 아니다.
- GPU 수를 바꿔도 초기 투자비와 기타 운영비를 자동 비례 변경하지 않는다. 규모의 경제나 다른 GPU 세대 가격을 임의로 가정하지 않는다.

## 가격과 비교

기본 목표 판매가격은 GPU 매출만으로 연 TCO를 회수하고 지정 매출 이익률을 확보하는 단가다. 계산은 `TCO / 판매시간 / (1−목표율)`이다. 소프트웨어 부가매출을 포함한 매출·경제적 잉여·손익분기 기본단가는 별도 펼침 영역에 표시한다. 부가서비스 추가 비용은 운영비에 포함해야 한다. 이익 표기는 자본비용까지 차감한 경제적 잉여이며 세후 순이익/현금흐름/IRR이 아니다.

경쟁사 비교는 데이터센터 전체 GPU 수와 무관하게 상품 GPU 수(초깃값8), GPU 모델, 지역, 계약, 네트워크 등으로 조회한다. 서버의 기존 동일조건 가격 서비스가 반환하는 USD/GPU-hour와 출처·수집시각을 사용한다. API 응답에 providerId를 추가하여 카탈로그 사업자명과 연결한다. 비교 이익률은 우리가 해당 공개 가격에 팔았을 때의 값이며 경쟁사의 실제 이익률이 아니다. 선택한 GPU 모델은 시장 조회 조건이고 기본 CAPEX가 해당 GPU의 견적이라는 의미가 아니다.

## 검증 및 배포

신규 POST `/api/v1/data-center-simulations`는 Spring에서 일회성 계산하며 저장하지 않는다. 기존 원가/IRR API 계약은 유지한다. API 테스트는 보고서 총액, 전기료/감가상각 중복 방지, 독립 전력 부하율, 자산별 할인율 계산, 잘못된 입력, 600,000-GPU센터와 8-GPU상품 조회를 검증한다. FE 테스트는 API 요청, 부가매출 구분, 가동률 민감도, 출처 링크와 escaping을 검증한다.

로컬 미리보기는 실행환경 소켓 제한, 운영 화면 직접 검증은 접근 인증 때문에 사용할 수 없다. 코드/자동 검증과 배포 성공 여부를 실제 브라우저 시각 검증과 구분한다.

## 가정 근거와 담당자 입력 개선

회색 비활성 입력을 제거했다. 보고서 모드에서 자본비용률·내용연수·잔존가치를 직접 수정하면 DISCOUNT_RATE로 자동 전환하여 입력값을 실제 산식에 반영한다. 전력 부하율을 직접 수정하면 independent로 전환하여 유료 가동률 변화가 입력값을 덮어쓰지 않게 한다. 전환 사유를 화면에 표시한다. 사용자가 명시적으로 보고서 모드를 다시 선택하면 IT 5년·시설 14년·잔존가치0으로 복원하며, 복원 사실과 자본비용률 미적용을 알린다. 입력값 범위 검증은 유지한다.

기존 잠금 이유는 보고서의 고정 연간 배분계수와 사용자 할인율 계산을 혼용하거나, 자동 연동 전력 부하율과 독립 입력을 동시에 적용하지 않기 위해서였다. 새로운 UI는 잠금 대신 산식 전환으로 같은 일관성을 유지한다. 요청 생성 시에도 보고서 모드의 내용연수/잔존가치가 불일치하면 조용히 기본값으로 덮어쓰지 않고 오류로 처리한다.

가정·근거 표에는 현재값, 출발값, 보고서 가정/보고서에서 도출/사용자 예시/사용자 변경 구분, 적용 여부, 선택 이유, 담당자 검토 메모를 표시한다. 잔존가치0와 할인율8% 및 목표마진20%를 보고서 원문 수치로 오인하지 않게 구분한다. 직접 입력한 설명은 외부 검증된 근거로 자동 분류하지 않는다.

결과의 계산 흐름은 실제 서버 결과와 제출한 가정을 사용하여 연간 원가 합산 → 판매 가능한 GPU 시간 배분 → 목표 매출 이익률 적용을 보여준다. 보고용 요약은 동일한 계산 스냅샷, 가정 목록/메모, 출처, 시장 관측 조건/수집시점, 미확인 항목과 제외 범위를 포함한다. 입력이나 근거 메모가 바뀌면 이전 결과와 요약을 지우고 재계산을 요구한다.

메모는 브라우저 작업 메모리에만 보관하며 API 요청에는 포함하지 않는다. 새로고침 시 사라진다. 복사는 사용자가 버튼을 눌렀을 때만 수행한다. 클립보드 접근이 제한되면 내용을 선택해 수동 복사할 수 있게 한다.
